# AI 调用接入经验手册(OpenAI 兼容网关实战)

> 来源:华为风格文档生成工具链 2.2.0 的真实接入与排障记录(2026-08)。
> 场景:本地应用直连 OpenAI 兼容网关(opencode-go)调用 DeepSeek v4-flash 等推理模型,
> 用于生产文档生成。本文把踩过的坑、根因与修复整理为可复用经验,供其他应用参考。

## 0. 架构背景(为什么这么设计)

```
应用业务层 → generator 适配器(唯一 AI 出口)→ OpenAI 兼容网关 → 模型
                │
                └→ 返回原始文本 → 剥壳/校验 → 进入业务(绝不直连渲染/执行)
```

- **适配器与业务解耦**:换模型、换网关、换协议只改适配器,业务零改动。
- **配置三阶段**:保存配置 → 测试连接 → 启用(激活)。测试不过不允许启用,避免坏配置上线。
- **密钥永不落业务代码**:环境变量或系统凭据管理器;配置接口只暴露"已配置/未配置"布尔值。

---

## 1. 模型 ID 大小写敏感 —— 显示名 ≠ API ID(必踩)

**现象**:请求返回 `{"type":"error","error":{"type":"ModelError","message":"Model DeepSeek V4 Flash is not supported"}}`(HTTP 401/400)。

**根因**:配置里写的是产品显示名"DeepSeek V4 Flash",网关只认 API ID `deepseek-v4-flash`。

**经验**:
- 模型名**从网关 `/models` 接口拉取**,不要相信文档里的显示名。
- 把模型名做成**可配置项**,不要把名字硬编码进代码。
- 适配器默认值用已实测的 ID,并加注释说明来源。

**代码**:`generators/codex.py` 的 `DEFAULT_MODEL = "deepseek-v4-flash"`(经 `/models` 验证)。

---

## 2. Cloudflare 风控拦截默认 User-Agent(隐蔽的 403)

**现象**:PowerShell/浏览器手工调用成功(200),但代码调用失败,`HTTP 403` + `error code: 1010`(Cloudflare 指纹拦截)。排查时手工复现永远成功、代码必挂,极难定位。

**根因**:Python `urllib` 默认 UA `Python-urllib/3.12` 被网关的 Cloudflare bot 防护识别为爬虫;浏览器 UA 放行。

**经验**:
- 遇到"手工通、代码不通"的 403,**先检查 User-Agent**。
- 给 HTTP 客户端设置浏览器风格 UA(兼容性最广)。
- 403 响应体里有 Cloudflare 错误码(1010 = 浏览器指纹),是定位铁证。

**代码**:`_post()` 请求头固定浏览器 UA:
```
Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36
```

## 3. 推理模型把输出预算"想完"了 —— 截断导致无正文(高危)

**现象**:任务偶发失败,响应 200 但内容为空,报"响应中没有可用文本"。复杂请求(长 prompt、要求输出大纲)高频触发,短请求正常。

**根因**:DeepSeek v4-flash 等推理模型会先输出 `reasoning`(思考)。`max_output_tokens=4096` 时,复杂任务思考就耗尽 4096 token,`message`(正文)还没开始就被截断——响应里只有 `reasoning`,没有 `output_text`。

**证据**:响应体
```json
{ "output": [{"type": "reasoning", ...}],          // 只有思考
  "incomplete_details": {"reason": "max_output_tokens"},
  "usage": {"output_tokens": 4096, "output_tokens_details": {"reasoning_tokens": 4096}} }
```

**经验**:
- **输出预算要给 reasoning + 正文留余量**:4096 对推理模型不够,默认提到 8192。
- **必须实现"截断重试"**:检测到截断(见第 4 条)且无正文 → 用 2 倍预算重试一次。
- **"提取成功但有部分文本"也要重试**:chat_completions 模式截断时可能返回残缺 JSON,提取不报错但内容不可用;响应标记截断就重试,拿完整输出。
- 重试有上限(1 次翻倍),避免无限循环与费用失控。

---

## 4. 两种协议的截断信号(缺一不可)

| 协议 | 截断信号 | 说明 |
| --- | --- | --- |
| responses | `incomplete_details.reason == "max_output_tokens"` 或 `status == "incomplete"` | OpenAI 新版接口 |
| chat/completions | `choices[0].finish_reason == "length"` | 经典接口 |

**经验**:同时支持两种协议的适配器,**两个信号都要检测**,否则切到另一种协议时截断重试静默失效(同类风险)。

---

## 5. HTTP 临时错误要有限重试,鉴权错误绝不重试

**现象**:真实运行中撞到 429(限流);直接失败导致用户任务中断。

**经验**:
- **重试集合**:`429, 500, 502, 503, 504`(限流 + 上游 5xx),最多 2 次,退避 `1.5s × 次数`。
- **不重试**:`401/403`(凭据/权限问题,重试无用且可能触发风控)、`400`(请求错误)。
- 网络层异常(超时/连接失败)同样有限重试。
- 与业务侧任务级重试(repair 回路)叠加时注意:适配器内部重试 + 上层重试是**多级防护**,各自设上限。

## 6. 密钥与敏感信息管理(红线)

- 密钥只走**环境变量**或**系统凭据管理器**(Windows Credential Manager),不进代码、不进配置文件、不进 git。
- **配置/状态接口只返回布尔值**(`credential_configured`),**永不回传密钥本身**;测试断言响应文本不含密钥。
- 失败信息**脱敏**:错误消息不含 prompt、密钥、输入正文、异常堆栈;只给稳定错误码 + 建议。
- 请求带 `store: false`,让网关不落盘存储本次对话。

---

## 7. 错误要"可读、可定位、可重试"

**反面教材**:所有生成器异常都归入通用"任务执行失败"(E001),用户无法判断是网络、限流还是配置问题。

**经验**:
- 生成器/适配器异常**单独分类处理**:给专属错误码(如 E010 = AI 通道调用失败)+ `retryable` 标记 + 具体文案 + `loc` 定位。
- 文案模板:`AI 通道调用失败：<具体原因>。请检查配置、网络与模型服务后重试…`。
- 任务失败保留原始输入,提供"重试"入口。

---

## 8. 连接测试(上线前必做)

- 每个 AI 通道配置后必须经过**连接测试**才能启用:发最小请求(`只返回 {"ok":true}`),校验返回的 JSON。
- 测试要有服务端超时护栏(如 60s),不能卡死 worker 线程。
- 测试结果展示延迟,便于用户对比通道质量。

---

## 9. 可配置项要暴露成 UI(不要只靠环境变量)

用户需要知道"当前在用哪个 baseURL、哪个模型、密钥配没配",并能修改:

- 展示:`当前通道 / 模型 / Base URL / 密钥状态(已配置|未配置)`。
- 可编辑:Base URL、模型 ID、协议模式、超时、推理强度、密钥。
- 多通道(如 NGA / opencode-go / 中转站)统一在一个界面:下拉选择 + 动态表单 + 共用「保存/测试/启用」。
- 非敏感配置持久化到设置文件,密钥进凭据管理器,环境变量作兜底(留空密钥 = 用环境变量)。

---

## 10. 双协议并存(responses + chat/completions)

- 网关可能只支持其一;适配器同时实现两种,`api_mode` 可配。
- payload 差异:
  - responses:`instructions`(系统提示)、`input`、`max_output_tokens`、`reasoning.effort`、`text.format`。
  - chat/completions:`messages[]`、`max_tokens`、`response_format`、`reasoning_effort`。
- 文本提取:responses 取 `output_text` 或遍历 `output[].content[].output_text`;chat/completions 取 `choices[0].message.content`。

---

## 11. 接入新 AI 通道的清单(照做即可)

1. 从网关 `/models` 拿**精确模型 ID**。
2. 手工(浏览器 UA)调一次最小请求,确认鉴权方式(Bearer / x-api-key)与协议。
3. 实现适配器:请求构造 + 文本提取 + 截断重试 + 临时错误重试 + 脱敏错误。
4. 实现配置三阶段(保存/测试/启用)与状态展示(不泄密钥)。
5. 测试矩阵:成功、401/403、429、5xx、超时、截断(reasoning 耗尽)、非法响应、超大响应、重试边界。
6. 上线前:连接测试 + 最小真实任务(Word/PPT 各一)+ lint 校验。

## 12. 推荐配置基线

| 项 | 推荐值 | 理由 |
| --- | --- | --- |
| 输出预算 max_output_tokens | 8192 | 推理模型 reasoning + 正文余量 |
| 截断重试 | 1 次,预算×2 | 覆盖 reasoning 耗尽,控制费用 |
| 临时错误重试 | 2 次,1.5s 退避 | 429/5xx 抖动自愈 |
| 超时 | 请求 300s;任务总超时 900s | 长文档生成 |
| 请求存储 | `store: false` | 隐私 |
| 响应上限 | 10MB | 防异常大响应 |

## 13. 排障速查(按现象)

| 现象 | 优先检查 |
| --- | --- |
| 手工通、代码 403 | User-Agent 指纹(第 2 条) |
| ModelError / 模型不支持 | 模型 ID 是否来自 /models(第 1 条) |
| 200 但内容为空 | 截断信号 + 预算(第 3、4 条) |
| 偶发失败、重试即好 | 429/5xx 重试策略(第 5 条) |
| 错误信息看不懂 | 异常分类与文案(第 7 条) |
