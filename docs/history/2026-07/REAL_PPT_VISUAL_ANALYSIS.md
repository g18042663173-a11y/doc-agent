## 现有 10 版式未覆盖或覆盖不足的真实版式

1. `profile_story` / 人物展播:照片 + 推荐元信息 + 推荐理由 + Q&A/经验分享 + 底部 ticker。出现频率最高之一。
2. `dense_matrix_table` / 合并单元格密集表:支持行分组、合并、长文本、勾选列、底部提醒条。
3. `process_analysis` / 根因流程分析:支持左右分析区、流程框、箭头、虚线边界、红色错误标记、黄色 callout、底部启示。
4. `photo_evidence_board` / 照片证据板:多图宫格、图片标注框/圈、旁侧说明、警示语。
5. `timeline_briefing` / 里程碑简报:顶部提示条 + 横向时间线 + 表格/行动条组合。
6. `notice_quote` / 合规通知与引用块:灰底大段文本、红色关键词、蓝色强调、下方启示框。

若必须控制新增版式数量,优先把 1-4 做成新 layout,5-6 可以先作为 `title_bullets` / `two_column` 的 richer block 演进方向。

## 风格方向

- 主色调方向:深红作为标题条、导航高亮、底部强调条和重点标题;灰色用于导航标签、说明框、表格底色;黄色用于提示条和 callout;蓝色偶尔用于链接/重点强调。照片色彩不可靠,此处只做方向描述。
- 结构密度:真实业务 PPT 明显偏高信息密度,大量表格、长段文字、流程图和多图拼贴。它不是营销型大留白风格,更像“培训/通报/复盘/展播”工具型材料。
- 标题体系:顶部红色通栏标题是最稳定的视觉锚点;右上灰色栏目导航多次出现,可视为 deck-level section nav。正文内常见红色小标题、黄色小标题条、蓝色强调词。
- 页脚/底部:不少页面使用红色通栏底部提示条,承担口号、提醒或征集信息功能;这不同于当前三段式密级页脚。
- 图文组织:真实页经常把“图、表、流程、文本、callout”混排在同一页,而不是单一 layout。

## 设计建议

本轮不实施,仅作为 DeckIR 版式集和 `hw_theme.json` 后续演进建议。

1. 新增“业务外壳 token”:在 theme 中抽象 `top_red_bar`、`right_nav_tabs`、`bottom_ticker_bar`、`yellow_notice_bar`、`gray_quote_panel`、`callout_box`。这些是跨页面稳定模式,不应散落在具体 layout 里。
2. 优先新增 `profile_story`:字段建议包含 `photo_ref/placeholder`、`subject_label`、`meta_items[]`、`reason_blocks[]`、`qa[]`、`footer_ticker?`。该版式在 P17、P21-P26 高频出现。
3. 强化 `table` 或新增 `dense_matrix_table`:字段建议支持 `row_groups`、`merged_cells`、`cell_emphasis`、`check_columns`、`note_bar?`。当前 12x8 简表无法覆盖 P03、P08-P10、P16、P18 的真实复杂度。
4. 新增 `process_analysis`:字段建议支持 `problem_summary`、`panels[]`、`nodes[]`、`edges[]`、`callouts[]`、`markers[]`、`lesson_box?`。这比 `chart` 更贴近 P11-P13 的真实复盘页。
5. 新增 `photo_evidence_board`:字段建议支持 `photos[]`、`annotations[]`、`caption_blocks[]`、`warning_lines[]`。可覆盖 P14、P19 这类活动/现场/证据照片墙。
6. `two_column` 不宜只支持文本列。建议后续把 column 内容抽象成 block list,允许 `text`, `bullets`, `table`, `image_grid`, `quote`, `callout` 等子块;若不改 IR,至少在 generator 层避免把复杂图文混排强塞进当前 `two_column`。
7. `chart` 的优先级不应只围绕柱/线/饼图。本批真实样本未见传统 chart,但流程图/时间线很多;如资源有限,先做 process/timeline,再考虑原生图表。
8. 封面建议增加 hero image 能力。P01 的真实封面不是纯文本封面,而是横向主视觉 + 右侧标题 + 底部品牌/口号。
