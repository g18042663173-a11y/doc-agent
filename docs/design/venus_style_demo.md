# 多框分布式软件架构打造业务规格

> 演示用途：验证一页复杂汇报页可由左右两栏和栏内堆叠组件组成。以下参数和工程项均为非业务示例数据。

## 采集机制

### 参数表

| 信道 | CDT 类型 | 数据维度 | 内存量 |
| --- | --- | --- | --- |
| 下行信道 | CDT-A | IQ 采样 / 时隙 | 512 MB |
| 上行信道 | CDT-B | LLR / 码块 | 384 MB |

### 数据流

CDT 缓存将采集数据按窗口缓存；数据分片按时隙切分并附带索引；L3 解析消费分片并输出可追溯记录。

### 采集机制结论

- 以 CDT 类型和数据维度作为采集参数的统一边界。
- 以分片索引连接缓存、处理和上层解析，便于回溯。

## 工程能力

### 能力表

| 工程能力 | 价值 | 技术点 |
| --- | --- | --- |
| 参数化采集 | 降低接入成本 | 类型化配置 |
| 分片处理 | 控制峰值内存 | 窗口与索引 |
| 并发调度 | 缩短处理时延 | 任务队列 |

### AS IS / TO BE

AS IS 采用串行任务与单一执行器；TO BE 采用并发调度与多执行器。任务节点使用 `job` 类型，执行模块使用 `module` 类型，颜色由 DeckIR 的 type 明确指定。
