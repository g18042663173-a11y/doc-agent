# 验收手册

## 自动验收

在仓库根目录执行:

```bash
python scripts/verify.py
```

通过判据:

- pytest 全绿。
- `app/parsers`、`app/ir`、`app/lint` 覆盖率均不低于 80%。
- 后端整体覆盖率不低于 70%。
- md/docx/xlsx/pptx 四格式均跑通 word 与 deck stub 链路,并产出 `report.json`。
- C0 Word/DOCX、Deck/PPTX、PPTX 合规报告均生成。

交付资产专项检查:

```bash
PYTHONPATH=backend python -m pytest backend/tests/test_delivery_assets.py -q
```

检查内容:parser 五类 manifest、8 页 PPTX expected、D001-D006、DOCX/Deck golden、lint 注入、expected hash、wheel manifest 和演示截图。

Windows 目标机执行:

```powershell
.\verify.ps1
```

## 人工终审

自动检查不替代人工终审。交付前必须人工完成:

- 在 Windows PowerPoint 打开生成 PPTX,检查字体替换、版面观感、元素重叠与可编辑性。
- 在 Windows Word 打开生成 DOCX,检查页眉页脚、表格跨页、导航窗格与可编辑性。
- 使用脱敏真实 docx/xlsx/pptx 各不少于 3 个样例跑解析回归。
- 在断网 Windows 机使用 wheelhouse 安装依赖并执行 `verify.ps1`。

人工结果记录不得用 Mac 截图代替。`docs/reviews/失败文案评审记录.md` 和 `主题校准评审记录.md` 的签字栏只有真实评审人可填写。

## 演示材料验收

```bash
python scripts/record_demo.py
```

检查:

- `samples/demo/screenshots/success.png` 展示 Word/Deck 成功退出。
- `samples/demo/screenshots/failure.png` 展示 D003 结构化失败。
- `samples/output/deck/deck_lint_violation_report/report.json` 包含期望的 HW-E01/E02 与 HW-W01/W02/W06/W07。
- 按 `samples/demo/recording_steps.md` 在 Windows Office 中补录可编辑性与字体观感。

## Windows wheelhouse 验收

联网准备机:

```bash
python scripts/make_wheelhouse.py --platform win_amd64 --python-version 3.12 --output wheelhouse
python scripts/hash_wheelhouse.py
```

断网 Windows 目标机:

```powershell
python -m pip install --no-index --find-links wheelhouse --require-hashes -r requirements-win312.lock
.\verify.ps1
```

先按 `docs/wheelhouse-win312-manifest.json` 复核 wheel 文件名与 SHA-256。Mac 生成 manifest 不等于 Windows 安装已通过。

## 失败提示检查

至少抽查以下反例:

```bash
PYTHONPATH=backend python -m app.cli.render --type word samples/ir/word_invalid_e004_ragged_table.json --output output/bad.docx
PYTHONPATH=backend python -m app.cli.render --type deck samples/ir/deck_invalid_d003_unknown_layout.json --output output/bad.pptx
```

通过判据:命令非零退出,stderr 中包含对应错误码和可执行建议。
