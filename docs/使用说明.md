# 使用说明

本工具链以 IR 为唯一契约,所有渲染入口都会先校验 IR,再生成可编辑 DOCX 或 PPTX。

## 常用命令

1. 解析输入文件:

```bash
PYTHONPATH=backend python -m app.cli.parse samples/input/quarterly_report.md --output output/document_ir.json
```

2. 生成 Prompt:

```bash
PYTHONPATH=backend python -m app.cli.prompt --kind deck --context output/document_ir.json --max-output-chars 6000 --output output/prompt.txt
```

`--max-output-chars` 控制给弱模型的输出预算提示;内网 4K-8K 输出模型建议使用 4000-8000。预算不足时 Prompt 会要求优先删减低价值内容,不得输出半截 JSON。

3. 渲染 WordIR:

```bash
PYTHONPATH=backend python -m app.cli.render --type word samples/ir/word_valid_03_table.json --output output/word.docx
```

正式详设可使用带控制信息表的 WordIR v1.2 样例；`document_control` 会在正文前生成产品/文档/密级/版本表与固定的拟制、审核、批准三行：

```bash
PYTHONPATH=backend python -m app.cli.render --type word samples/ir/word_valid_05_document_control.json --output output/detail-design.docx
PYTHONPATH=backend python -m app.cli.check output/detail-design.docx --classification 内部公开 --output-dir output/check-detail-design
```

`prepared`、`reviewed`、`approved` 均保留 `name` 和 `date` 字段；未知时填 `null`，渲染仍保留对应角色行，不得省略。

4. 渲染 DeckIR:

```bash
PYTHONPATH=backend python -m app.cli.render --type deck samples/ir/deck_valid_full.json --output output/deck.pptx
```

5. 复检产物:

```bash
PYTHONPATH=backend python -m app.cli.check output/word.docx --classification 内部公开 --output-dir output/check-word
PYTHONPATH=backend python -m app.cli.check output/deck.pptx --classification "HUAWEI CONFIDENTIAL" --output-dir output/check-deck
```

6. 一键验收:

```bash
python scripts/verify.py
```

Windows 目标机使用:

```powershell
.\verify.ps1
```

## Stub 断网演示

```bash
python scripts/demo_e2e.py samples/input/parser_samples/md_sample_01.md --target word --generator stub --output-dir output/demo-word
python scripts/demo_e2e.py samples/input/parser_samples/md_sample_01.md --target deck --generator stub --lint --output-dir output/demo-deck
```

StubGenerator 不调用外部 AI,用于 CI、断网环境和内网接入前的环境冒烟。

## 先分析、再选择页数/深度

只做文件规模分析并输出三档建议,不生成 IR 或 PPT:

```bash
python scripts/analyze.py samples/input/需求说明.docx --generator stub --output output/analysis.json
```

按用户选择生成 Deck;`--pages` 可覆盖档位默认页数:

```bash
python scripts/generate.py samples/input/需求说明.docx --generator stub --depth 标准 --lint --output-dir output/deck-standard
python scripts/generate.py samples/input/需求说明.docx --generator stub --depth 详细 --lint --output-dir output/deck-detailed
python scripts/generate.py samples/input/需求说明.docx --generator stub --depth 标准 --pages 12 --lint --output-dir output/deck-12
```

两个新参数都不传时仍走原有单次生成路径。详细档先产独立大纲,再按最多 4 页一批生成
并校验 DeckIR,最后合并并再次校验。截断/修复记录见输出目录的
`generation_manifest.json`;完整设计与 NGA 接入约定见 `GENERATION_NOTES.md`。

## 固定交付样例

附录 B 三个固定输入可直接用于演示:

```bash
PYTHONPATH=backend python -m app.cli.parse samples/input/需求说明.docx --output output/需求说明.document_ir.json
PYTHONPATH=backend python -m app.cli.parse samples/input/销售台账.xlsx --output output/销售台账.document_ir.json
PYTHONPATH=backend python -m app.cli.parse samples/input/项目汇报.pptx --output output/项目汇报.document_ir.json
```

`项目汇报.pptx` 固定为 8 页,含表格、原生图表、演讲备注和空白页。逐页 expected 位于 `samples/expected/项目汇报.pptx.expected.json`。

## DocumentIR 1.0 兼容读取

解析器当前统一生成 DocumentIR 1.2。仓库的 CLI 演示和 Web 作业目录会落盘
`document_ir.json`,因此读取入口保留了对已生成 1.0 文件的兼容:

- 读取 1.0/1.1 时先在内存中把版本迁移为 1.2,并在 `warnings` 中记录迁移事实。
- 迁移后重新执行 1.2 的格式/内容一致性、表格规整和预览上限约束;不合法的旧数据仍会被拒绝,不会绕过新契约。
- 兼容读取不会覆写原文件。需要长期保存时,应重新运行解析命令生成 1.2 文件,或将校验后的模型重新序列化。

因此,存量 1.0 中间产物无需单独执行批量迁移才能继续使用,但它们首次读取后必须满足
1.2 约束。DocumentIR 是流水线中间产物,不承诺跨主版本永久保存。
