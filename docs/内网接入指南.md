# 内网接入指南

本项目外网阶段已经把真实依赖收敛成两个插座：模型插座 `NGAClient`，渲染插座 `HuaweiSkillRenderer`。进入内网后只补这两个适配器，不改解析、DeckIR v1.1/WordIR、历史、模板、配色、前端和备份迁移流程。

## 1. 外网默认配置

外网可端到端跑通的默认配置：

```env
LLM_PROVIDER=stub
PPT_RENDERER=stub
PPT_COMPLIANCE_GATE=warn
USE_LANGGRAPH=false
DATA_DIR=data
OUTPUT_DIR=outputs
```

`mock` 和 `python_pptx` 仍是兼容别名。`presenton` 已不支持。

## 2. 接入 NGA

需要修改的代码位置：`doc_agent/llm/nga_client.py`。

适配器必须保持这个接口：

```python
class NGAClient(BaseLLMClient):
    def generate_json(self, prompt: str) -> dict[str, Any]:
        ...
```

内网接入时只做三件事：

1. 按 NGA 真实协议发送 `prompt`、`LLM_MODEL`、认证信息。
2. 从响应中提取模型文本。
3. 解析为严格 JSON，失败时抛出可读异常，不返回半结构数据。

内网 `.env` 示例：

```env
LLM_PROVIDER=nga
LLM_BASE_URL=http://nga-service.example
LLM_API_KEY=replace-with-intranet-token
LLM_MODEL=glm-4.7
```

如 NGA 真实协议不是 OpenAI-compatible，不要改 planner；只在 `NGAClient.generate_json` 内转换。

## 3. 接入华为 PPT 渲染 Skill

需要修改的代码位置：`doc_agent/renderers/huawei_skill_renderer.py`。

适配器必须保持这个接口：

```python
class HuaweiSkillRenderer(BaseRenderer):
    def render(self, ir: dict[str, Any], output_path: str | Path) -> Path:
        ...
```

上游只传稳定 `DeckIR v1.1`。它保留基础 layout，并支持 `cards/chart/image`、`source_refs`、`intent`、`importance`、`visuals`、`chart`、`footer/confidentiality` 等扩展字段。官方 Skill 2026-03-10 后默认以 `html2pptx` 作为主力生成方式，`generate.py` 只作为快速原型或结构简单 PPT 的兜底方式。内网接入时先确认 Skill 暴露的是 HTML 输入、JSON 输入，还是二者都支持，再在 `HuaweiSkillRenderer` 里把 DeckIR v1.1 转成 Skill 需要的格式。

如果使用 `html2pptx`，必须补齐的输入契约：

```text
html2pptx:
- HTML document structure
- CSS class naming and allowed inline styles
- page size and safe area
- card/header/footer components
- chart/table/image handling
- DeckIR v1.1 fields to HTML/CSS component mapping
- output path behavior
- Node.js/package/runtime command
- error format
```

如果回退使用 `generate.py`，必须补齐的 JSON 字段清单：

```text
cover page:
- required fields
- optional fields
- image/logo fields
- coordinate or layout fields

content page:
- title field
- bullet/body fields
- card fields
- chart/image fields
- source_refs/intent/importance handling
- table fields
- footer fields

two-column page:
- left/right title fields
- left/right body fields
- width/position rules

global:
- slide size
- theme colors
- fonts
- output path behavior
- error format
```

内网 `.env` 示例：

```env
PPT_RENDERER=hw_skill
PPT_COMPLIANCE_GATE=error
```

不要在外网实现红卡片、多栏精确坐标、html2pptx 或华为母版复刻；这些都属于内网 Skill 适配范围。

## 4. 合规检查

外网已实现独立检查器：

```bash
python -m doc_agent review-pptx outputs/demo.pptx --json
```

当前规则覆盖：

- 中文字体：必须为 Microsoft YaHei/微软雅黑，否则 Error
- 英文字体：建议为 Arial；大数字可用 Impact，否则 Warning
- 字号：小于 6 pt 为 Error，单页超过 3 种字号为 Warning
- 颜色：不在黑/红/白/灰范围内时提示 Info
- 动画/转场：不允许
- 线宽：参考 0.5 pt
- 页脚：`HUAWEI CONFIDENTIAL`

内网拿到官方 `review.py` 后，可以替换或对齐检查规则，但报告结构保持：

```json
{
  "score": 88,
  "summary": "0 Error, 2 Warning, 0 Info",
  "items": [
    {
      "severity": "Warning",
      "code": "font.size.unexpected",
      "message": "Found non-standard font sizes: 18.",
      "slide_index": 2
    }
  ]
}
```

## 5. 离线安装和预览导出

Windows 11 内网桌面优先使用免安装运行包。在同架构外网 Windows 11 构建机执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/export-windows-runtime.ps1
```

把 `release/doc-agent-win11-runtime-*.zip` 拷进内网，解压后运行：

```powershell
Start-DocAgent.cmd
```

这条路径不在内网机器执行 pip/npm 安装，后端直接托管 `ppt-agent-frontend/dist/`。

通用离线依赖包：

```bash
pip wheel -r requirements-runtime.txt -w wheelhouse
```

外网默认使用 LibreOffice 和 Poppler 做页面图片预览：

```env
SOFFICE_PATH=/path/to/soffice
PDFTOPPM_PATH=/path/to/pdftoppm
```

命令：

```bash
python -m doc_agent export-images outputs/demo.pptx --out-dir outputs/demo-pages
```

缺工具时会返回明确错误。官方 Skill 里的 `export_slides.py` 可能通过 PowerPoint COM 导出图片；如果内网必须使用 COM，执行前要提醒用户先保存所有已打开的 PPT，因为脚本可能强制关闭 PowerPoint 窗口。

## 6. 验收顺序

1. 外网默认 stub 生成仍通过。
2. 设置 `LLM_PROVIDER=nga` 后，NGA 能返回合法 DeckIR/WordIR JSON。
3. 设置 `PPT_RENDERER=hw_skill` 后，华为 Skill 能从 DeckIR 输出 PPTX。
4. `PPT_COMPLIANCE_GATE=error` 下，不合规 PPTX 会阻断任务并写入历史错误。
5. 前端工作台能显示模型插座、渲染插座、合规状态、历史下载和合规报告。

回归命令：

```bash
.venv/bin/python -m pytest
cd ppt-agent-frontend && npm run build
cd ppt-agent-frontend && npm run test:coverage
cd ppt-agent-frontend && npm run test:e2e
```
