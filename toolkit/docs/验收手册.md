# 验收手册

## 自动验收

在仓库根目录执行:

```bash
python scripts/verify.py
```

通过判据:

- pytest 全绿。
- `app/parsers`、`app/ir`、`app/lint` 覆盖率均不低于 80%。
- 后端整体覆盖率不低于 70%。
- md/docx/xlsx/pptx 四格式均跑通 word 与 deck stub 链路,并产出 `report.json`。
- C0 Word/DOCX、Deck/PPTX、PPTX 合规报告均生成。

交付资产专项检查:

```bash
PYTHONPATH=backend python -m pytest backend/tests/test_delivery_assets.py -q
```

检查内容:parser 五类 manifest、8 页 PPTX expected、D001-D006、DOCX/Deck golden、lint 注入、expected hash、wheel manifest 和演示截图。

Windows 目标机执行:

```powershell
.\verify.ps1
```

`verify.ps1` 只使用 `.venv\Scripts\python.exe`,并写出
`output/environment_report.json`。有本地 `wheelhouse/` 时,pytest 会额外执行离线
`pip --dry-run --require-hashes`,确认 CPython 3.12 / win_amd64 的传递依赖闭包。

模板与图表专项:

```powershell
$env:PYTHONPATH = Join-Path $PWD "backend"
.\.venv\Scripts\python.exe -m pytest backend/tests/test_template_contracts.py backend/tests/test_template_rendering.py backend/tests/test_web_api.py backend/tests/test_chart_quality.py -q
```

检查内容包括模板资源上限、路径穿越、宏/ActiveX/OLE、外部/悬空关系、动画清除、
运行时容量回退、W201/W202、API 资产白名单,以及正/负/混合/全负柱图、窄区间折线、
字面量百分比、长中文类目和饼图适用性。

## 可靠性与工作台测试

离线发布门禁与 QA 汇总:

```powershell
.\.venv\Scripts\python.exe scripts\reliability_test.py
```

该命令生成 `output/qa/report.json`、`pytest-junit.xml` 和 `index.html`；报告只列测试名、失败类型和错误码，不保存输入正文、Prompt、密钥或堆栈。

开发/CI 的浏览器工作台检查不属于生产依赖，也不参与 PPT 渲染:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev-ui.txt
.\.venv\Scripts\python.exe scripts\reliability_test.py --ui
```

检查覆盖一次结构化失败及失败报告下载、一次带模板的成功生成、桌面 1280px 与 390px 窄屏、控制台错误和横向溢出。真实模型仅在已显式配置生成器时单独执行:

```powershell
.\.venv\Scripts\python.exe scripts\reliability_test.py --real-model
```

## Office 视觉导出

Office COM 只用于 Windows 验收，不参与生产渲染。先由人工审核一套固定 Office/字体环境导出的 PNG 作为 baseline，之后禁止自动覆盖 baseline：

```powershell
.\scripts\office_visual_export.ps1 -Kind deck -InputPath output\hit_template_acceptance\deck_hit_template.pptx -OutputDir output\qa\office-export
.\.venv\Scripts\python.exe scripts\visual_diff.py --baseline <approved-png-dir> --candidate output\qa\office-export\deck_hit_template-png --output output\qa\visual-diff.json
```

任一页面超过默认图像差异阈值时 `visual_diff.py` 返回非零，必须人工复核；Word 使用同一导图脚本的 `-Kind word` 生成 PDF，再由人工检查分页与编辑性。

## 人工终审

自动检查不替代人工终审。交付前必须人工完成:

- 在 Windows PowerPoint 打开生成 PPTX,检查字体替换、版面观感、元素重叠与可编辑性。
- 在 Windows Word 打开生成 DOCX,检查页眉页脚、表格跨页、导航窗格与可编辑性。
- 使用脱敏真实 docx/xlsx/pptx 各不少于 3 个样例跑解析回归。
- 在断网 Windows 机使用 wheelhouse 安装依赖并执行 `verify.ps1`。

人工结果记录不得用 Mac 截图代替。`docs/reviews/失败文案评审记录.md` 和 `主题校准评审记录.md` 的签字栏只有真实评审人可填写。

HIT 真实模板基准使用 `C:\Users\GSQ\Downloads\哈尔滨工业大学ppt模板.pptx`。产物应
无 Error、无 HW-W03、每页有密级、无 `XXXX`、包关系完整,并能由 PowerPoint 16
正常打开和导出 PDF/逐页 PNG。自动导图与联系表只证明可打开和没有明显空白/裁切,
最终“是否像模板、是否拿得出手”仍需人签字。

## Windows wheelhouse 验收

联网准备机:

```bash
python scripts/make_wheelhouse.py --platform win_amd64 --python-version 3.12 --output wheelhouse
python scripts/hash_wheelhouse.py
```

断网 Windows 目标机:

```powershell
python -m pip install --no-index --find-links wheelhouse --require-hashes -r requirements-win312.lock
.\verify.ps1
```

先按 `docs/wheelhouse-win312-manifest.json` 复核 wheel 文件名与 SHA-256。Mac 生成 manifest 不等于 Windows 安装已通过。

## 失败提示检查

至少抽查以下反例:

```bash
PYTHONPATH=backend python -m app.cli.render --type word samples/ir/word_invalid_e004_ragged_table.json --output output/bad.docx
PYTHONPATH=backend python -m app.cli.render --type deck samples/ir/deck_invalid_d003_unknown_layout.json --output output/bad.pptx
```

通过判据:命令非零退出,stderr 中包含对应错误码和可执行建议。
